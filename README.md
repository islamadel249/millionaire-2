# تحدي المليون – أبطال المعرفة

تطبيق ويب عربي (RTL) لإدارة مسابقة أوائل الطلبة بين فريقين في مدرسة حسان بن ثابت.

## التشغيل
```bash
bun install
bun run dev      # http://localhost:8080
bun run test     # اختبارات منطق المسابقة
```
كل البيانات تُحفظ في متصفح الجهاز (localStorage). المؤثرات الصوتية مولّدة برمجيًا. الخطوط العربية تُحمَّل من Google Fonts؛ دون إنترنت يُستخدم خط النظام البديل.

## الصفحات
| الصفحة | الوظيفة |
|---|---|
| `/` | الشاشة الرئيسية، اسم المدرسة (انقر لتعديله)، رفع الشعار، مقدمة قابلة للتخطي |
| `/setup` | معالج الإعداد: الفريقان ← المحتوى ← نظام المسابقة ← القواعد ← المراجعة، مع حفظ القوالب |
| `/play` | لوحة المقدم: التحكم الكامل بالسؤال والمؤقت والمساعدات والنقاط والسجل |
| `/display` | شاشة العرض للطلاب (افتحها من زر «شاشة عرض ثانية» واسحبها إلى الشاشة الثانية) |
| `/bank` | بنك الأسئلة: إضافة/تعديل/حذف/بحث/ترتيب/معاينة/استيراد وتصدير JSON وCSV |
| `/history` | سجل المسابقات السابقة مع الطباعة والتصدير |
| `/settings` | الصوت والهوية ومسح البيانات |

## خطوات السؤال (لوحة المقدم)
عرض السؤال ← (في المواجهة: تحديد الفريق) ← اختيار الإجابة ← تثبيت ← كشف النتيجة ← احتساب النقاط ← (سرقة اختيارية) ← السؤال التالي.
الكشف والاحتساب خطوتان منفصلتان، وكل محاولة تُحتسب مرة واحدة فقط مهما تكرر الضغط.

## الأنماط
- **التناوب:** يتبادل الفريقان الدور؛ تنتهي الجولة عند استيفاء كل فريق عدد أسئلته.
- **المواجهة المباشرة:** يحدد المقدم الفريق صاحب الأولوية يدويًا، أو يُستخدم مفتاحا لوحة المفاتيح **A** (الفريق الأول) و**L** (الفريق الثاني) — أول ضغطة تُسجَّل. لا يقيس التطبيق زمن الاستجابة بأي طريقة أخرى.
- **النهائي:** تصميم خاص، رهان اختياري، إخفاء رصيد المنافس اختياريًا، ونقاط تُضاف أو تستبدل الرصيد حسب الإعداد.
- **التعادل:** يُضاف سؤال فاصل من الأسئلة غير المستخدمة (الأصعب أولًا).

## بنك الأسئلة
نموذج: `public/samples/question-bank-sample.json`. أعمدة CSV:
`text,a,b,c,d,correct,subject,grade,topic,difficulty,points,time,explanation` (correct = 0..3 أو a..d، difficulty = easy|medium|hard).
الأسئلة المرفقة **تجريبية وليست معتمدة من المناهج العُمانية**.

## الاختبارات المنفذة (`src/lib/quiz/engine.test.ts`)
التناوب وتبادل الدور، منع الاحتساب المزدوج، فصل الكشف عن الاحتساب، رفض الانتقالات غير الصحيحة، انتهاء الجولة والانتقال، سلم المليون، خصم الخطأ، المواجهة وأول ضغطة، السرقة ونقاطها المستقلة، المؤقت المعتمد على الموعد النهائي، انتهاء الوقت ومنع الإجابة، تجميد الوقت، حذف إجابتين، الفرصة الثانية، النهائي (استبدال/رهان)، السؤال الفاصل، الحفظ والاستعادة، استيراد وتصدير JSON وCSV.

## ما لم يُنفذ بعد
- تصويت جمهور حقيقي (يُعرض كمحاكاة موسومة بوضوح).
- أجهزة ضغط لاسلكية مخصصة (مدعوم فقط: لوحة المفاتيح A/L).
- العمل دون إنترنت بعد إغلاق المتصفح (لا يوجد Service Worker بعد؛ التطبيق يعمل محليًا بعد التحميل).
- فتح نافذة العرض تلقائيًا على الشاشة الثانية (يجب سحبها يدويًا).

## النشر على Vercel

### لماذا يظهر خطأ `Cannot resolve entry module index.html`؟
Vercel يكتشف المشروع كـ«Vite عادي» ويشغّل `npx vite build` مباشرة. هذا التطبيق لا يحتوي
`index.html` أصلًا — نقطة الدخول يولّدها `vite.config.ts` — فيفشل البناء فورًا.
العلاج: أجبر Vercel على استخدام `npm run build`، وأجبر البناء على إخراج نسخة Vercel.

### ملفّان يضمنان ذلك (موجودان بالفعل في المشروع)
1. **`vercel.json`** في الجذر:
   ```json
   {
     "framework": null,
     "buildCommand": "npm run build",
     "build": { "env": { "NITRO_PRESET": "vercel" } }
   }
   ```
   `framework: null` يمنع مُعرِّف Vite الذي ينفّذ `npx vite build`.
2. **`vite.config.ts`**: السطر `nitro: { preset: "vercel" }` يبني نسخة Vercel
   (مجلد `.vercel/output`) خارج بيئة Lovable. داخل Lovable يُتجاهل هذا السطر
   ويُبنى نسخة Cloudflare كما هو الحال دائمًا — أي أن النشر من Lovable لا يتأثر.

> ملاحظة: `NITRO_PRESET=vercel` وحده لا يكفي عند البناء داخل Lovable لأن البيئة
> تتجاهل المتغيّر وتثبّت نسخة Cloudflare؛ لذا يُثبَّت الهدف في `vite.config.ts`.

### النتيجة المتوقّعة من البناء
```
.vercel/output/
├── config.json     ← يوجّه كل المسارات إلى /__server (الروابط الداخلية تعمل)
├── functions/      ← كود السيرفر (SSR)
└── static/         ← الملفات الثابتة
```

### إعدادات يجب التأكد منها في مشروع Vercel
1. **Root Directory** = المجلد الذي يحتوي `package.json` و`vite.config.ts` و`src/` و`public/`.
2. **Framework Preset** = `Other`، و**Build Command** = `npm run build`.
3. **Output Directory** = فارغ (Vercel يقرأ `.vercel/output` تلقائيًا).
4. تأكد أن الملفات مرفوعة فعلًا في المستودع:
   `git ls-files | grep -E "vite.config|package.json|vercel.json"`
5. `.vercel/` مضاف إلى `.gitignore` (ناتج بناء، لا يُرفع).
6. لو تكرر خطأ `index.html` فمعناه أن `vercel.json` أو `vite.config.ts` غير موجود
   في المجلد الذي يُبنى منه — راجع البندَين 1 و4.

### النشر من جهازك
```bash
bun install
bun run build          # يُنتج .vercel/output
npx vercel deploy --prebuilt
```
